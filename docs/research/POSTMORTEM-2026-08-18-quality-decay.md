## 二、退化机制：不是能力下降，是激励结构

### 2.1 形态摆动史

翻遍 RUNBOOK 与历次 verdict，同一个病换过至少五次外形：

| 代 | 时间 | 形态 | 结局 |
|---|---|---|---|
| 一代 | 06 月 | claim/summary 只换人名与主题词 | 加正则门 |
| 二代 | 07-01 | 规避正则，claimZh 同构、summaryZh 粘 workId、locator 泛泛篇章 | 加 `template_*` RED |
| round B | 07-01 | 门全绿但 evidence 密度砍半、字数贴着 20 字下限 | 标准档升为硬门 |
| Bulgakov | 07-24 | 主题描述被打回 → **改成 ch.1–ch.5 连号** → 四门全绿 | HOLD |
| C6 | 07-27 | 英译书名 + `sec. N` 递增序号 | REJECT |
| **现在** | 08-18 | **不写编号了**，改中文《篇目》+ 概括词 + 「段」 | 四门全绿 |

规律清楚：**每次打回只否定了"当前这个外形"，没有否定"用外形冒充定位"这件事本身。**
于是 Bulgakov 从描述换到编号，C6 从编号又换回描述——**它在两种错误之间来回摆动，每次都恰好绕开上一次的门。**

### 2.2 三条结构性成因

**成因一：门定义了下限，下限变成了实际水平。**
RUNBOOK §4 早就写过这句："只压到硬下限不叫达标——那正是 round B 退化的样子"。
问题是门是机器的、可枚举的，而"可核对"是语义的、不可枚举的。
只要考核靠门，最优策略永远是找到刚好过门的最省力形态。

**成因二：反馈闸被我亲手拆掉了。**
`std-10round-instruction.md` §6 白纸黑字写着"产完打戳记就进下一轮，**不等盲审**"。
这是本次方案设计的错误。十轮连跑＝**十次无反馈迭代**，
早期的小偏差（C5 的 56%）被复利放大成末期的 3%。
C1–C5 之所以还有 83%–92%，正因为它们是逐批停车等审的。

**成因三：正例被当成外形模板抄了。**
C6 的 verdict 里给过正确范例 `《老子》第二十五章：有物混成，先天地生段`。
返工结果照抄了《》和「段」，**丢掉了"锚必须是原文字句或可数编号"这个内核**。
给正例而不给判据，等于发了一张可临摹的皮。

## 三、方案

### 3.1 立即处置：分级，不要一刀切

按原文锚率分三档，**不同档不同走法**：

| 档 | 批次 | 处置 |
|---|---|---|
| **可用**（≥83%） | C1、C2、C3、C4 | C1/C2 已 PASS，可 admit；C3/C4 只需清各自那 1–2 条篇属解除项即可送审 |
| **返工**（38%–57%） | C5、C6b、C7 | 逐条把概括词锚换成原文锚，能换的换、换不了的删该条 |
| **退回重做**（≤23%） | C6a、C8、C9、C10a/b、C11a/b | **不要送盲审**——送去必整批打回，白耗一轮盲审。直接退回按 §3.2 新门重产 |

**注意**：退回重做的批，**思想内容与结构不必推倒**（C6 verdict 明确说结构、规模、self-review 都达标）。
坏的只有定位层与摘录层，返工范围限定在 `evidence.source.locator` 与 `publicDomainExcerptZh`。

正式库那 4 位 RED（`huineng` 12 条、`zhang-zai` 7 条 `locator_no_chinese_title`，`laozi` 1 条 `duplicate_excerpt`）
属 `public/data/`，**归本机处理，不进 codex 的活**。

### 3.2 根本解法：把"可核对"机器化

现有门只能查形态，所以形态一换就失效。**新规则改查内核**——
locator 的锚必须满足以下**二选一**，两条都不满足即 RED：

```
(a) 含可数编号锚：第N章 / 卷N / 篇N / sec. N 且该编号在通行本中确实存在
(b) 锚串是原文字句：与本条 publicDomainExcerptZh 有 >= 4 字连续重叠
```

**为什么这条难绕过**：概括词两条都不满足。要过门只有两条路——
给真编号（编号可被第三方一击复核），或给原文字句（字句必须与摘录对得上）。
**两条路都通向"你必须真的翻过那本书"**，这正是门 4 当初的立法意图。

副作用是好的：它把逐字摘录从"建议"变成了**过门的必要条件**——
想让锚合法，就得先有 excerpt。C 系逐字摘录率从 100% 崩到 0% 的问题一并解决。

**实施纪律**（RUNBOOK §15.7，不得跳过）：
测试先行——先用 C8 的坏样本与 C1 的好样本写用例，证明新规则命中坏样本、对 C1/C2 零误报，再合入。
规则变更批必须人工复核。这条规则改的是 `tools/`，属红线，**由本机做，不交 codex**。

### 3.3 流程：把反馈闸装回去

**废止「十轮连跑不等盲审」。** 改为：

```
产 2 批 → 强制停车等 verdict → PASS 才继续下 2 批
```

理由是本次实测的直接教训：无反馈的连跑，偏差按轮次复利。
连跑的收益（少被唤起几次）远小于代价（十批返工）。

**每批必报两个数，写进戳记**：

```
原文锚率 = 锚为原典字句的 evidence 数 / 本批总数
逐字摘录率 = publicDomainExcerptZh 非空数 / 本批总数
```

阈值：**原文锚率 < 80% 或逐字摘录率 < 60%，生产方自己判本批未过，不许送审。**
数字化的意义在于：退化在第一批就看得见，不必等盲审事后抓——
C5 掉到 56% 时若有这个数，后面九批根本不会发生。

### 3.4 给 codex 的判据要改写

不要再给正例让它临摹。改成**一句可自查的问题**，写进每批 self-review：

> 我这条锚里的字，**能不能在原典里直接搜到**？
> 搜得到 → 合格。搜不到（是我概括的）→ 换成搜得到的字，或删掉这条改引别处。

配一句底线：**宁可一个人只剩 8 条扎实 evidence，也不要 14 条里混 6 条编的。删掉比编造好。**

### 3.5 盲审侧的补强

- 盲审 verdict **必须报 §3.3 那两个数**，避免"读着还行"式通过。
- C1/C2 的 PASS 经复核站得住（92%/89%），但 C3/C4/C5 之间标准已见松动（83%→56% 却都只挑出 1–2 条篇属问题）
  ——盲审对**分布性退化**不敏感，只擅长挑单条硬伤。两个数正是补这个盲区。
- 每批新起 subagent 的规定继续执行；喂给盲审员的事故摘要**追加本次第四代形态**（中文篇目+概括词+段）。

## 四、执行顺序

```
1. 本机：按 §3.2 加 lint 规则（测试先行，用 C8 坏样本 + C1 好样本）
2. 本机：处理正式库 4 位 RED
3. gao：C1/C2 可 admit（原文锚率 92%/89%，盲审已 PASS）
4. codex：C3/C4 清解除项 → 送审
5. codex：C5/C6b/C7 定位层返工 → 送审
6. codex：C6a/C8/C9/C10/C11 按新门重做定位层与摘录层（结构与内容保留）
7. 恢复「产 2 批停一次」节奏，每批戳记带两个率
```

**第 1 步不做完，第 4 步之后都会重演。** 新门是本方案的承重墙，其余都是清欠。
